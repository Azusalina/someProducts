# someProducts-monitor — Description

A minimalist desktop dashboard with a fully transparent default background for Arch Linux, KDE Plasma 6 and Wayland. The product lives in `core/`; design notes, verification logs and screenshots live in `docs/`. No Git commands were used.

Default compact size: **300 × 360** (previously 360 × 480). Minimum native widget size: 200 × 120. someProducts-monitor is installed locally on this machine and its user service is running. Add it to the desktop using the README instructions.

The dashboard defaults to no filled background or border, with no card surfaces, shadows or blur. **Settings → Appearance** accepts `#rrggbb` text, border and background colors. Background opacity 0% and border width 0 preserve full transparency; raise these values for a colored board or outline. Native window frames, Plasma edit handles and scrollbars remain managed by Qt/Plasma.

## Modules

- **PROTON / WIFI / BLUETOOTH:** connection/radio status and native settings entry points. Proton is a transparent capsule button with animated hover outline/press scale, a pulsing connected dot and an opening animation. Server and Kill Switch status are on hover. Proton retains its GUI; VPN and Kill Switch changes happen there. Enable these modules in **Settings → Modules**. See [CONNECTIVITY.md](CONNECTIVITY.md).

- **CPU:** smooth utilization history as the main body, 9 px percentage in the upper-right corner. Hover for logical core count and available temperature. Up to 40 real samples (about 20 seconds at the 0.5-second cadence) accumulate after opening. The first sample is unknown until a second counter reading arrives.
- **RAM:** smooth utilization history and a corner percentage; used/total GiB in the hover tooltip. Used RAM is total minus `MemAvailable`, so reclaimable caches are accounted for.
- **GPU:** device utilization where available, temperature and VRAM where exposed. NVIDIA uses `nvidia-smi`; AMD uses sysfs. Intel uses deduplicated DRM client engine counters readable by the current user. Intel's value is the busiest aggregated engine, capped at 100%, with the label **User-session engines**; it is not an all-users hardware counter. Missing values display **—**, not a fabricated zero. **Next GPU** appears when multiple devices are detected.
- **PING:** configurable target labels/icons and latency. Targets start empty. The service measures ICMP round-trip time to the URL's hostname, not HTTP page response time. A timeout can mean ICMP is blocked; it does not prove the website is down.
- **MEDIA:** only a progress bar and Pause/Resume button, with no title, source, timestamps or heading on the desktop. MPRIS supplies duration, position, rate and control capability; position advances locally between snapshots and is clamped to the known duration. Unknown progress leaves an empty track. Select a preferred player in Configure → Media, or leave Automatic to prefer a playing source. Browser videos need Plasma Browser Integration or the browser's MPRIS support. Buttons are disabled when control is unavailable.
- **CAVA:** a flowing curve from 32 live spectrum amplitudes behind the media controls, tinted with the board's text color at 40% opacity by default (18% before 1.6), with a 2 px stroke for visibility. The installed CAVA binary analyzes the explicitly selected default playback sink's `.monitor` source through PulseAudio/PipeWire-Pulse. No microphone fallback or synthetic waves are used. The collector starts on demand, stops after five seconds without requests, follows default-output changes, and discards stale frames. Missing CAVA, audio server or output leaves no curve. Configure → Media can hide it or change opacity.
- **TERMINAL:** an interactive per-widget shell using a Linux PTY, `pyte` VT parser and native QML Canvas/TextInput. No browser terminal or external terminal window is required. Click Start terminal to create a session in the `monitor/` directory; Bash uses `--noprofile --norc -i` to avoid implicit startup commands. It supports Unicode/IME, ANSI colors, alternate screen, arrows, function keys, Ctrl+C/D, resize, bracketed paste and 500-line scrollback. Ctrl+Shift+C copies the visible viewport, not a mouse selection. It is a compact terminal: mouse reporting, image protocols, clickable links and full Konsole compatibility are not implemented. Terminal height/font are configured separately.
- **NOTE:** click directly into the text area, type plain text, and leave it on the desktop. Changes save after 400 ms and on focus loss. Your normal KDE keyboard/input-method support handles input. Notes are stored locally in the widget's Plasma configuration.

## Widget catalog folders

- User-installed widgets: `~/.local/share/plasma/plasmoids/` (this machine: `/home/a/.local/share/plasma/plasmoids/`).
- System widgets: `/usr/share/plasma/plasmoids/`.
- someProducts-monitor source: `monitor/core/plasmoid/`.
- Installed someProducts-monitor: `~/.local/share/plasma/plasmoids/local.monitor.dashboard/`.

The user is handling cleanup manually. To identify an unfamiliar user widget, read its `metadata.json` and `KPlugin.Name`. Removing a custom widget via Add Widgets → Uninstall is preferable to deleting folders while Plasma has it loaded. System widgets belong to installed packages.

For a development preview, **Bridge offline** means `./scripts/start.sh` is not running. The bridge listens only on `127.0.0.1:17341`. It accepts native widget requests with a custom header and rejects browser Origin headers and foreign Host headers. It exposes telemetry, validated MPRIS PlayPause, fixed native settings destinations, CAVA frames and terminal session operations. Notes never pass through the HTTP bridge; there is no hosted database. This local API is not a boundary against other processes running as your user.

Terminal sessions have independent random tokens, bounded input queues and at most eight simultaneous sessions. Recomposition retains the session owner; disabling the terminal, removing the widget or stopping the service closes its shell. An abandoned session expires after five minutes without polling/input. Service restart ends all sessions. Output and commands are not written to HTTP logs or saved transcripts. Programs running in the terminal can still write their own files. Existing notes and layout settings are not rewritten on upgrade; obsolete module IDs are filtered and new choices are appended.

The installer creates a separate runtime virtual environment and copies only product backend files. It removes the retired quota/news collectors and QML cards. A narrowly scoped migration disconnects only this product's previous Claude status-line command, restoring the prior status-line setting when its saved backup exists and preserving unrelated settings. Existing account files, historical backup/cache files and external developer tools are retained.

## Validation

```bash
./scripts/verify.sh
./scripts/package.sh
```

The verification script runs backend tests, real QML interaction tests and an isolated MPRIS fixture. It reuses a running someProducts-monitor bridge or starts/stops a temporary one. The MPRIS fixture never plays media or controls real players. A separate CAVA test plays a generated tone only into a temporary silent sink, then removes that sink and verifies the default output is unchanged. Test-only dependencies: `plasma-sdk`, `python-dbus`, `python-gobject`, `python-pillow`, `pyside6`.

See `VALIDATION.md` for tested behavior and remaining hardware-specific limits. `preview-transparent.png` is an RGBA export of the default dashboard; `preview-colored.png` shows a colored background and outline. The `preview-config-*.png` images show the separate configuration pages. Transparent pixels may appear black in some viewers. Screenshots contain a clearly named integration-test media fixture and a local test Ping target, not a default target or real video.

### Battery, power modes and timers — 1.8 (2026-10-08)

Battery and Timers are independent full-width modules, selectable and reorderable in Configure → Modules. New instances include both by default; existing explicit selections remain intact unless `refresh-desktop.py --reveal-power-timers` is requested. This upgrade enabled them in the sole existing desktop instance. Its old order remains unchanged, so new modules appear at the bottom and may require scrolling. Timers always places countdown on the left and stopwatch on the right, including at a 200 px dashboard width.

`backend/power.py` polls the UPower aggregate DisplayDevice and power-profiles-daemon every two seconds on a separate thread. It publishes only battery percentage, state, battery charge/discharge power and the applicable time estimate, plus supported/current profiles. Battery watts are the net battery energy rate, not total machine consumption; charging watts represent charge input. Missing/non-finite measurements remain unknown. No battery serial/model identifiers are returned. Powersave maps to `power-saver`, Regular to `balanced`, Performance to `performance`. A validated property write is confirmed by reading ActiveProfile; there is no automatic mode change or privilege escalation. Permission failures remain visible in the card. Sources: [UPower Device](https://upower.freedesktop.org/docs/Device.html), [power-profiles-daemon D-Bus interface](https://freedesktop-team.pages.debian.net/power-profiles-daemon/gdbus-org.freedesktop.UPower.PowerProfiles.html).

Keep awake uses a persistent session-bus helper and PowerDevil AddInhibition with policy mask 5: InterruptSession (1) plus ChangeScreenSettings (4), as defined in the [PowerDevil policy header](https://github.com/KDE/powerdevil/blob/master/daemon/powerdevilpolicyagent.h). The same persistent helper owns a ScreenSaver.Inhibit cookie to prevent idle locking, which would otherwise override PowerDevil screen inhibition. Both cookies are explicitly released on shutdown and disappear on bus disconnect. The dashboard tooltip explains that idle locking is inhibited; manual locking remains available. It blocks automatic suspend and screen power changes; it does not promise to override a deliberate suspend, shutdown, lid action or critical-battery policy. Each widget owns a random lease token, renewed every two seconds, expiring after ten seconds without a heartbeat (collected at the next two-second sweep). One bridge helper holds the inhibition while at least one owner remains. Disabling/hiding/removing the battery module releases only its own lease. The bridge explicitly terminates its helper on shutdown; closing the parent pipe also releases it after an abrupt bridge death. It never releases another application's inhibitor. PowerDevil deliberately defers enforcement for five seconds. The helper waits for an allowed ActiveInhibitions entry covering both sleep and idle before acknowledging success; the widget shows Applying until then. A denied request fails and releases its cookie. Sources: [PowerDevil implementation](https://github.com/KDE/powerdevil/blob/master/daemon/powerdevilpolicyagent.cpp). Power state is confirmed before the On label appears. Root-level PowerOwner persists across module reconstruction.

`backend/timers.py` keeps independent token-scoped pairs using a monotonic clock. Start is idempotent, Pause retains fractional elapsed time, Reset restores the configured duration/offset, and reaching zero stops countdown without stopping the stopwatch. The clock excludes time spent suspended. TimerOwner polls at 250 ms and remains at dashboard root so reordering cannot reset a running pair. Hiding the Timers module closes its pair; abandoned sessions expire after 60 seconds without requests. The manager admits at most 16 sessions. Live progress is in memory; it resets on bridge/desktop-shell restart or prolonged loss of the widget connection. Persisted time/color/style settings remain in each widget's own KConfig, separate from live state. Minimal is proportional text, Digital uses monospace, Ring uses a remaining-duration arc for countdown and a repeating minute arc for stopwatch. Countdown completion is visual (Done), with no audible alarm.

Native Configure → Timers and the standalone preview use staged `cfg_*` values. Both timers independently accept 0–86400 seconds (countdown minimum 1), blank/default or valid #rrggbb color, and three style choices. Apply a new time to reset/pause that side; color/style changes leave live time intact. Preview settings width is 760 px so seven tabs remain legible. Default surfaces remain fully transparent. The terminal reader also now catches a close-before-selector-registration race discovered during lifecycle tests.
