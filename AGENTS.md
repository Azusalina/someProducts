# Product documentation

Apply this convention to every current and future product under this workspace:

- Keep the product's existing README filename (for example, `README.md` or `readme.md`).
- Give each README exactly two content sections: `What is it?` and `How to use`.
- `What is it?` briefly explains the product and its purpose.
- `How to use` covers prerequisites, opening or running the product, essential interaction, configuration, and installation or removal when applicable.
- Store other documentation in an adjacent lowercase `description.md`: detailed feature descriptions, architecture, file inventories, sources, methodology, assumptions, limitations, development and maintenance instructions, validation results, and project history.
- When reorganizing an existing README, preserve the displaced content in `description.md`, merge with any existing description rather than overwriting it, and keep relative links working.
- Link to `description.md` from one of the README's two sections; do not add a third documentation section.
- Preserve existing documentation language and unrelated work.
