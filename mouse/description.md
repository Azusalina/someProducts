# Mouse — implementation and maintenance

## Scope

Native GTK 3 editor for G502 X LIGHTSPEED receiver `046d:c547` and wired `046d:c098`. It edits five existing onboard profiles, each with up to 11 physical buttons and 11 G-Shift bindings. The diagram follows the factory profile's button ordering. The mechanical free-spin wheel lock is not a programmable button. Wheel rotation is preserved; the tilt controls are editable.

Supported outputs: mouse buttons, one keyboard key with any combination of left/right Ctrl, Shift, Alt, and Super, HID consumer/media keys, disabled buttons, and onboard DPI/profile/G-Shift functions. Firmware macros and unfamiliar encodings are displayed as original raw bindings and retained unchanged. This version does not create timed macros, application-specific profiles, enable disabled profile slots, or change DPI, lighting, polling rate, profile names, or wheel-resolution settings. Keyboard characters follow the OS keyboard layout; a shortcut must also be accepted by the target application/compositor.

## Architecture

- `app.py`: native GTK UI, mouse drawing, profile/layer selection, binding editor, event test field, local drafts, backup restore, asynchronous hardware work.
- `bindings.py`: four-byte binding codec, human-readable action names, HID key and modifier tables from Solaar.
- `hardware.py`: Solaar receiver discovery, strict G502 X filtering, onboard reads, checksum validation, raw-sector patching, conflict checks, automatic backups, verified writes, profile activation.
- `mouse`: executable launcher; prefers the adjacent virtual environment when present.
- `setup-device-access.sh`: narrow udev `uaccess` rule for the receiver and wired mouse. No world-writable input devices and no persistent root daemon.
- `install.py`: user application-menu/command installation and removal.
- `tests/`: sector-preservation, invalid input, binding encoding, transaction, and GUI fixtures.

Uses the installed Solaar Python implementation of HID++ feature `0x8100` (ONBOARD_PROFILES). No Solaar GUI/rules daemon is started. Standard HID mouse/keyboard reports generated by onboard memory work under Linux without X11 injection or `/dev/uinput`. Therefore mappings run immediately and persist across login with no autostart service.

Raw profile bytes, including DPI, reserved data, lighting, and unknown macros, are preserved. Only selected four-byte binding entries at offsets 32 (normal) and 96 (G-Shift) plus the trailing CRC16 change. The writer rereads the device before applying; a changed profile/layout or serial mismatch requires a fresh read. Writes create an atomic JSON backup first, then read back the exact sector. No-change saves skip flash writes. Individual profile writes are verified separately; saving multiple profiles is not an atomic hardware transaction. On a disconnect, some profiles may already have been saved; reconnect and read, or restore from backups.

Restore stages button bindings only. A backup contains full raw profiles as evidence/recovery data, but the GUI deliberately retains current non-button settings when restoring. A local file lock serializes this app's operations. Other configurators cannot share that lock; close them while writing. The device remains usable after the GUI closes.

## Sources

- [Solaar HID++ implementation](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/hidpp20.py): onboard profile reads/writes and four-byte button formats.
- [Solaar capabilities](https://pwr-solaar.github.io/Solaar/capabilities/): onboard settings and Linux receiver support.
- [libratbag G502 X wireless device definition](https://github.com/libratbag/libratbag/blob/master/data/devices/logitech-g502-x-wireless.device): model identity and HID++ backend.
- [Logitech G502 X quick-start guide](https://www.logitech.com/assets/66193/2/g502-x-artanis-web-qsg.pdf): physical buttons and onboard profiles.

Solaar is an external GPL-2.0-or-later dependency installed through its published package; this project does not copy its source into the application.

## Development and validation

Run `.venv/bin/python -m unittest discover -s tests -v` and `./mouse --demo` for the hardware-free UI fixture. Hardware operations must be tested on an awake connected G502 X; unit tests do not prove flash behavior, real shortcut delivery, power-cycle persistence, or wired-mode support.

Host discovery on 2026-10-13: Arch Linux, GTK 3 available, libratbag 0.18 installed but `ratbagctl list` returned no devices. Solaar 1.1.20 in a local virtual environment successfully queried the c547 receiver, G502 X LIGHTSPEED (HID++ 4.2), all five profile slots, 11 normal/G-Shift bindings, and the existing active shortcuts. The Arch package mirror transaction failed DNS resolution; no system Solaar installation resulted. Further validation results are recorded here after implementation.

Validation completed on 2026-10-14:

- All 18 unit tests passed: keyboard/mouse encodings, preservation of unknown actions, exact preservation of unrelated sector bytes, checksum/offset rejection, stale state and layout guards, backup-before-write, no-change flash avoidance, readback failure handling, and disabled-profile activation.
- GTK workflow checks passed under Xvfb: normal and G-Shift editing, multiple staged profiles, local draft loading, and saving all changed profiles. The complete 1080-pixel desktop rendering was visually inspected.
- The GUI loaded all five profiles and the active profile's 11 bindings from the real receiver as the normal user after installing the scoped udev rule. User launcher installed; `desktop-file-validate` passed.
- A real wireless flash round trip changed a normal binding to Ctrl+C and a G-Shift binding to Super+Tab in disabled profile 3, verified readback, and restored both. The complete final snapshot equaled the starting snapshot: all profile bytes, enabled states, active profile, and onboard mode were preserved. Automatic original backups remain in the user's config directory.
- Physical button presses in target applications, unplug/power-cycle persistence, and wired connection remain manual validation boundaries. The GUI includes a focused input field that displays received key/modifier and mouse-button events.

The installed host icon theme emits GTK size-field warnings; it does not prevent launching or reading profiles. The irrelevant Solaar rules-module Wayland injection notice is filtered, because this app uses onboard HID output rather than Solaar rules.
